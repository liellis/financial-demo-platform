## 快速启动

要求 Python 3.11+、Node.js 20.19+/22.12+、JDK 21（需要 `java` 和 `javac`）、Git。当前依赖已锁在 `requirements.lock`、`frontend/package-lock.json`。

```bash
cd /Users/louis/work-space/Code-projects/Codex/bank-ontology-platform
uv --cache-dir .cache/uv venv .venv --python python3.12
uv --cache-dir .cache/uv pip install --python .venv/bin/python -r requirements.lock
npm --prefix frontend ci --cache .cache/npm
npm --prefix frontend run build
```

已安装的环境可以直接运行以下步骤，无需重新创建虚拟环境。

```bash
# 一个终端同时启动 API 与 Worker；Ctrl+C 停止两者
.venv/bin/python scripts/start.py

# 或分别启动：
# 终端1：API，默认只监听本机回环地址
.venv/bin/python -m backend.api

# 终端2：独立持久任务 Worker
.venv/bin/python -m backend.worker

# 可选：为自动化脚本显示管理员 API 令牌（界面使用账号密码登录）
.venv/bin/python -m backend.manage token admin
```

打开 [工作区](http://127.0.0.1:8000)，使用默认账号 `admin`、密码 `admin123` 登录；在配置中心 → 账号与密码中可修改密码。默认账号仅首次创建，后续重启不会重置密码。登录会话有效期8小时，退出会撤销当前会话，修改密码使该账号所有会话失效。密码使用随机盐 PBKDF2-SHA256 哈希保存，浏览器仅在内存中保留会话令牌。

接口契约在 [OpenAPI](http://127.0.0.1:8000/docs)。前端修改时也可运行 `npm --prefix frontend run dev`，访问 `http://127.0.0.1:5173`，API 仍使用8000端口。前端构建产物由 API 托管，API 启动前须完成构建。

## 用户接入流程

1. 在“数据源接入”上传 ZIP、选择本地目录，或提交受控 HTTPS Git 链接。上传保存实际内容，不伪称某个 Git Commit；Git 接入解析实际 Commit。浏览器目录选择是上传内容，不是授权服务器读取本机任意路径。
2. 在任务中心选择快照、创建 AST 解析任务，再点击“确认启动”。等待真实 Worker 完成，查看解析覆盖和诊断。不会执行上传项目的代码、构建脚本、注解处理器、Git hooks、LFS 或子模块。
3. 管理员配置 OpenAI-compatible 连接，在表单中勾选并登记当前确切模型主机。默认选择“直接填写 API Key”，在密码框填写新密钥并保存；或在高级模式引用后端环境变量。登记/保存本身不调用模型，随后点击真实最小样例验证。只有验证指纹、用途及现行授权满足门禁时，才能创建规则抽取任务。如果部署设置了固定 BOS_MODEL_HOSTS，则需遵守其名单，界面不能扩大范围。
4. 抽取结果先逐条核验证据位置、源码引用及代码映射；无效输出不会进入候选。专家在“知识审核”核对条件、结果、范围、例外和固定源码，保存修改后需单独重新批准。
5. 管理员在“版本与审计”选择已批准规则并填写原因，发布固定清单。业务—代码映射图使用已发布的确切方法版本。历史 Release 不覆盖，回退只切换默认知识指针。

当前接入限额：UTF-8；Java/Markdown/TXT/SQL/XML；单文件1 MiB、累计25 MiB、最多1000文件，单次 Java 分析最多200文件。排除 `.git`、`.env`、构建目录等；超限拒绝，不假装完整分析。建议上传一个业务切片。

Git 首批仅实现公开/既有服务端授权可读的 HTTPS 仓库；域名由 `BOS_GIT_HOSTS` 控制。URL 不接受用户口令、Token、查询参数。私有 Git 凭据连接器尚未实现，不应把 Token 拼到 URL。

## 模型与凭据

用户已确认采用 OpenAI-compatible 接口；具体 Endpoint/模型在运行后由管理员配置。应用不会自动连接外部模型。

凭据有两种明确分开的方式：

- **直接填写 API Key（默认）：**在密码框输入密钥。后端以 Fernet 认证加密保存到独立的 `.data/credentials/`；配置、任务和审计仅含不透明引用。保存后输入框清空，不返回密钥，不写入应用的 localStorage/sessionStorage。API 和 Worker 共用数据目录，无需重启即可读取。
- **引用环境变量（高级）：**填写变量名称，如 `BOS_MODEL_API_KEY`，不能填写实际 API Key。变量名使用大写字母、数字和下划线，以字母开头；API/Worker 的运行环境都须配置其值。

页面提供“使用 DeepSeek 配置”：基础地址 `https://api.deepseek.com`、模型 ID `deepseek-flash`。应用自动追加 `/chat/completions`；此名称与路径已核对 [DeepSeek 官方文档](https://api-docs.deepseek.com/)。规则 JSON 抽取明确使用非思考模式，避免有限输出预算被推理内容占用；这不代表已通过用户真实模型质量验收。

默认 `BOS_MODEL_HOSTS` 留空时，模型页会显示“待登记主机”。管理员勾选授权并点击“登记此模型主机”后，主机精确匹配规则持久化到数据库，API 与 Worker 共享，无需重启。非管理员不能登记，未登记主机仍被拒绝。若设置了非空 `BOS_MODEL_HOSTS`，它是部署级固定白名单，界面授权不能绕过；错误提示会明确要求部署管理员修改并重启。

```bash
# 以下仅适用于“引用环境变量”高级模式；直接填写 API Key 不需要设置此变量。
# 以下 BOS_MODEL_HOSTS 是可选的部署固定限制；采用页面登记时不设置它。
export BOS_MODEL_HOSTS='model.your-bank.internal'
export BOS_MODEL_API_KEY='由受控凭据系统注入'
.venv/bin/python -m backend.api
# Worker 必须使用同一环境与数据目录，配置后重启 API 和 Worker。
```

页面 API 基础地址例如 `https://model.your-bank.internal/v1`；它自动追加 `/chat/completions`。支持 JSON object 输出、有限响应大小/超时；响应 `model` 必须与配置的模型 ID 一致，别名/版本差异需先配置明确 ID。本地 HTTP 仅允许回环主机，其他 Endpoint 要求HTTPS且主机已登记或列入部署白名单。URL 不能包含用户名、密码、查询参数或片段；错误提示区分格式错误、HTTPS要求、域名未登记、凭据格式、401鉴权、402余额、403权限、404模型/地址、429限流、空输出与输出截断。

本地凭据库目录权限700、文件600，主密钥位于该目录的 `master.key`，不得单独丢失或提交代码库。备份/迁移需保全密文和主密钥；丢失/损坏时拒绝解密，不自动生成替代密钥或伪称可用。这是单机开发模式，不能防止已控制本机账户的攻击者；多节点/生产部署须替换为独立 Secret Manager/KMS，并配置传输与权限边界。

此增量仅开放 `RULE_EXTRACTION` 用途，验证有效期24小时；配置、凭据、模板/Schema 或证据验证器变化使旧指纹失效。诊断验证发送固定最小样例，正式抽取还要求显式允许发送当前工作区样例代码。正式抽取在创建任务时先生成确定性分批计划（不调用模型），按序列化后的用户消息计入源码、实体及 Schema，确保每次调用不超出 `max_input_chars`。配置中心提供每次调用的源码/文档总行数上限，默认100，范围1–2000（含空行和注释），同时服从字符预算。短方法优先完整发送；长方法按行片段发送并强制标注完整性待核对，不将局部理解冒充完整方法。单行仍超过字符预算时明确返回文件、行号、实际字符数和上限。模型输入采用逐行的原始绝对行号与文本记录，便于逐字引用。页面先显示调用次数、逐批范围及输出 Token 上限，确认启动后才依次调用。

新版任务每批校验通过后保存检查点，暂停/继续不重发已校验批次。单批证据或结构校验失败会隔离该批并继续其他批次；全部通过才显示成功，存在缺口则显示部分完成。仅把已校验批次写为候选，并强制增加覆盖不完整待核对项，不能直接批准。旧版任务仍保留原执行方式，可通过创建重试任务升级并复用成功检查点。已知失败可在任务详情“创建重试任务”，计划和模型指纹一致时复用已校验批次，仍需确认启动。响应超时、响应中断及租约过期的未知批次不会自动重发，但不阻止其他批次；显式选择包含未知批次后才能重放，可能重复计费。管理员在配置中心保存全局默认值，其他业务角色只读；配置持久化并记录审计。新任务固定配置快照，旧任务继续原计划；失败任务创建重试时采用最新默认值，计划改变则不复用旧检查点。旧失败任务保留历史，可用相同入口创建分批任务。模型调用只理解当前批次；跨批次业务依赖及独立文档到代码的映射仍需人工核对，不能将分批完成视为完整语义理解。

配置中心同时管理响应等待超时（默认120秒）、临时故障额外重试次数（默认2次）、退避基数（默认5秒）。新任务固定执行策略。连接失败、连接超时、429及500/502/503/504按指数退避有限重试，支持Retry-After（上限1小时），等待状态持久化，Worker可处理其他任务，不用阻塞sleep。重试可能增加费用，页面显示含重试的剩余请求上限。401/402/403等鉴权、余额或权限故障停止任务并保留检查点，需处理配置后恢复；不无界重发。单批校验错误不自动收费重试。适配器另检查响应总时长，防止持续零碎字节无限占用Worker；套接字读取本身仍受读取超时限制。

仅当引用文本在本批次中逐字出现且位置唯一时，允许确定性校正模型返回的行号，并保存可查看的校正记录；不改写引用文本，仍检查原始快照、批次范围和实体映射。改写、缩略、重复歧义及未发送的引用不会被模糊匹配接受。

## 规则抽取子任务管理

侧栏“规则抽取子任务”提供独立入口，父任务详情可直接跳转。支持父任务/状态/文件/错误码筛选、分页、成功进度、源码范围及逐次调用/人工操作记录；admin/developer可以单项或同父任务批量重试失败范围、暂停/继续待执行子任务，reviewer只读。成功子任务不可重放；UNKNOWN须明确授权可能重复计费的重试。暂停/继续保留退避时间和次数，跳过会保留覆盖缺口。

单项重试在原父任务内排队，不复制整个任务。已结束父任务只调度选中范围；父任务尚未启动或暂停时仍等待原有启动/继续。存在暂停或未调度范围时进入WAITING_SUBTASKS，不冒充成功。旧版任务只读，可创建恢复任务保留已校验检查点。详见 [设计与实现](子任务管理设计与实现_M1_07.md)。

## 存储与身份

- 默认 `.data/studio.db` + 内容快照文件，使用 SQLite 本地配置；用于先验证纵向链路，不代表已完成 PostgreSQL/Neo4j 部署验收。
- 设置 `BOS_DATABASE_URL=postgresql+psycopg://...` 可启用 PostgreSQL 记录适配器。数据目录切换不自动迁移旧库；已有数据迁移需单独规划。
- 设置 `BOS_NEO4J_URI/USER/PASSWORD` 可启用 Neo4j 发布投影；准备并核验图后才在关系库事务内切换指针。图失败不会自动降级为发布成功。没有配置时明确显示 `local-manifest`，不假称 Neo4j 已接入。
- 首批单租户、单工作区；界面使用账号密码登录，初始管理员账号为 admin。自动化 API 仍支持四类独立 Bearer 令牌：admin 管理配置/发布，developer 接入和运行任务，reviewer 审核，agent 只读已发布清单。页面不提供身份模拟切换；每个 API 服务端检查角色。
- 凭据、数据库、快照和测试运行目录均在忽略列表；不要提交 `.data/`、`.env`。当前不提供企业 SSO、项目级 ABAC 或生产审计防篡改能力。
- 单 Worker 使用进程锁与持久领取状态。暂停在安全边界保存检查点，取消等待当前操作确认；租约失效记录未知，不自动重跑潜在已发出的模型请求。

## 阶段边界

本次已实现可运行的“上传 → AST → 模型接口 → 候选 → 审核 → 发布 → 图谱”基础链路，以及双语主题。Joern 选型/真实依赖复杂项目、对象/模块元模型编辑、通用人工确认项、完整模型路由/修订管理、跨数据库真实故障验收尚待后续一期增量；Context/MCP、三个 Agent 客户端及 Action 引擎仍按 M2/M3 交付，页面不模拟成功。

### 配置中心

所有设置统一从侧栏“配置中心”进入：

- **模型连接与验证**：连接地址、模型 ID、凭据、域名授权、输入/输出预算、温度、源码发送许可、能力验证及停用。修改模型运行参数仍需创建不可变配置版本。
- **抽取与执行参数**：默认批次行数、响应超时、临时故障重试次数及退避基数；仅管理员可修改，新任务固定配置快照。
- **界面偏好**：中英文、浅色/深色/跟随系统，立即生效并保存于当前浏览器；登录页保留语言和主题选择。
- **账号与密码**：查看当前账号并修改密码；需验证原密码，新密码至少8位，修改后重新登录。

任务页仍可选择已验证模型，并提供配置中心快捷入口。此次入口调整不迁移或修改已保存的模型、凭据和任务数据。

### 模型辅助恢复审批

在“规则抽取子任务”选中父任务后，可点击“生成模型处理建议”。平台使用任务固定的已验证模型，仅提交失败/隔离/未知子任务的错误码、状态与源码范围等诊断元数据，按相同原因分组生成原因分析和修正提示；不发送源码正文。每次生成最多一次模型调用，可能计费；生成请求具有幂等标识，结果持久化，断线不会自动重复发送。一次支持最多100个异常子任务，建议审批有效期1小时。

可执行建议默认选中已知失败组，用户可取消勾选并批量“批准建议并重试”。审批核验建议版本、子任务修订、模型指纹和角色权限；成功子任务保持原样。重试绑定已批准的修正提示，例如要求引用必须位于所关联实体内，仍执行原有结构/证据校验，不能直接接受失败规则。未知请求默认不选中，重放仍需独立确认可能重复计费。配置/权限/余额、超预算等问题仅给人工前置处理建议，不自动更改设置、不跳过范围、不批准或发布规则。审批、执行和修正提示可追溯。
